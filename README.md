# 划词助手

> 选中一段文字，浮窗自动弹出来。点一下「总结 / 翻译 / 是什么？」，答案就地流式打出来。

Windows 桌面小工具。后台静默运行，托盘一个图标，不占任务栏。
在 Word、PDF 阅读器、浏览器、微信里划词都能用 —— 它走的是系统级的鼠标钩子，不挑软件。

**零第三方依赖。** 全部功能只用 Python 标准库 + ctypes 手写，不需要 `pip install` 任何东西。

---

## 它长什么样

1. 在任意软件里**拖拽选中**一段文字
2. 鼠标松开的地方弹出一排按钮：`总结` `翻译` `是什么？`
3. 点一个 → 浮窗原地展开，答案一个字一个字地流出来
4. 点浮窗外面 → 关掉

按钮和请求是分开的：**不点按钮就不会调用 AI**，不会白白烧钱。

## 开始用

```
1. 双击  启动.bat          （后台静默启动，没有黑框）
2. 右下角托盘出现一个蓝色图标
3. 右键托盘图标 → 设置 → 填 API Key
4. 随便找个地方划一段字试试
```

调不出来的时候双击 **调试启动.bat** —— 它保留控制台，会打印每一步在干什么。

### 首次启动

没填 API Key 的话，程序会自己把设置窗口弹出来，并给一条系统通知。
填完保存即可，设置存在这里：

```
%APPDATA%\ai-huaci\config.json
```

**故意放在项目目录外面** —— 这样万一你把项目传上 GitHub，Key 不会被一起带走。

## 动作可以自己改

托盘右键 → 设置 → **动作** 标签页。

三个默认动作（总结 / 翻译 / 是什么？）都能改名字、改提示词，也能删掉或新增。
提示词就是你希望 AI 怎么处理这段文字，写清楚就行。

几个例子：

| 按钮名 | 提示词 |
|---|---|
| 改通顺 | 把这段话改得更通顺、更书面，保持原意。只输出改完的结果。 |
| 找 bug | 下面是一段代码。指出里面可能的 bug 或边界问题，按严重程度排序。 |
| 写给老师看 | 把下面这段转成给中学老师看的说明，别用术语，300 字以内。 |

## ⚠️ 需要知道的事

这个工具实现「划词」的方式，决定了几件绕不开的事。用之前请都看一眼。

### 1. 它靠模拟 Ctrl+C 抓取选中文字

Windows 没有给普通程序提供「读取当前选中文字」的接口。可行的办法只有一个：
**模拟按一下 Ctrl+C，把内容复制到剪贴板，读出来，再把你的剪贴板还原回去。**

带来的后果：

- **剪贴板会被短暂占用**（通常几十毫秒）。程序会先备份、再还原，但如果原来剪贴板里是**图片或文件**，还原不了，会被冲掉。
- 在**终端里划词会打断正在跑的命令** —— 因为终端里 Ctrl+C 是「中断」。
  所以程序默认在终端窗口（cmd / PowerShell / Windows Terminal / Git Bash）里不响应划选。
  **别关掉这个开关**，除非你知道自己在干什么。
- 某些软件不吃模拟按键（部分以管理员权限运行的窗口、个别游戏），这些地方划词不会弹窗。

### 2. 杀毒软件可能会报警

程序做了三件杀软看着很可疑的事：**装全局键盘鼠标钩子**、**模拟按键**、**读写剪贴板**。
渲染成「你可能被监控」的样子。如果被拦了，加白名单即可。

### 3. 它不联网，除非你点按钮

程序本身只在**你点击动作按钮之后**才向你自己配置的那个 API 地址发一次请求。
没有遥测、没有埋点、没有自动更新、不往任何第三方地址发东西。
你的 API Key 只存在本机 `%APPDATA%\ai-huaci\config.json`，只发给你自己填的那个接口。

### 4. 这是个人自用工具

没有自动更新、没有崩溃上报、没做多屏 / 高 DPI 之外的兼容性打磨。
代码写成什么样就是什么样，欢迎自己改。

```
├── icon.ico         托盘 / 窗口图标

```

### 线程模型

理顺这个，整个东西才稳：

```
主线程      tkinter 主循环。所有界面操作都在这。
钩子线程    全局鼠标钩子。回调里只往队列丢一条消息就立刻返回 ——
           回调卡住 = 全系统鼠标卡住。
AI 线程     每次请求开一条，流式结果也是丢队列。
托盘线程    Shell_NotifyIcon 的消息循环。
```

所有跨线程通信都走**同一个 `queue.Queue`**，主线程用 `after(30ms)` 定时取。
这是唯一安全的做法：tkinter 不是线程安全的，别的线程碰 widget 会直接炸。

## 自己动手改代码时，两个坑

写在这里，省得你再踩一遍。

### 1. ctypes 必须声明 `argtypes` / `restype`

64 位下不声明的话，ctypes 会把指针参数当 `int` 处理，直接抛
`int too long to convert`。**这个错误语法检查看不出来，只有运行到那一行才炸。**

### 2. `INPUT` 结构体在 64 位下必须是 40 字节

`SendInput` 用的那个 `INPUT`，内部的 union 里**必须放着最大的成员** `MOUSEINPUT`（32 字节）：

```python
class _INPUTunion(ctypes.Union):
    _fields_ = [('mi', MOUSEINPUT), ('ki', KEYBDINPUT)]
```

只写 `KEYBDINPUT`（24 字节）的话，整个 `INPUT` 会变成 32 字节而不是 40，
`SendInput` 会返回 0 并报「参数无效」(87)，**而且什么都不解释**。
这个 bug 的表现是「Ctrl+C 完全没反应」，能查很久。
